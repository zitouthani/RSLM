Le projet

Un assistant documentaire que l’on peut inspecter.

Les réponses documentaires s’appuient sur une recherche vectorielle, un reranking et un contexte sélectionné. Les sources sont présentées avec leurs documents et pages.

01

Recherche dans vos PDF

Importez un corpus autorisé, indexez ses passages et retrouvez des informations avec des références documentaires.

02

Pipeline RAG traçable

Suivez les candidats retrouvés, les scores de classement, le contexte transmis au modèle et les sources associées.

03

Administration et sauvegardes

Gérez le corpus depuis l’interface et disposez d’outils locaux de sauvegarde et de restauration.

Architecture

Des composants spécialisés, reliés simplement.

Navigateur → Streamlit → FastAPI → Ollama
                         └→ Qdrant
PDF → extraction → passages → embeddings → index vectoriel
                     └→ reranking → contexte → réponse sourcée

Questions courantes

Avant de lancer RSLM.

Le site héberge-t-il le chatbot ?

Non. GitHub Pages sert uniquement le site statique ; l’API, Ollama et les documents s’exécutent localement.

Les PDF ou les modèles sont-ils fournis ?

Non. Ajoutez uniquement un corpus que vous êtes autorisé à traiter. Les documents, index et modèles téléchargés ne sont pas inclus dans le dépôt.

Quelle option d’installation choisir ?

Le parcours local lance l’API et l’interface depuis Python. Docker Compose conteneurise l’API et Qdrant, mais Ollama reste sur l’hôte. Consultez le guide avant de choisir.

Démo locale, pas un service public hébergé.

Le site présente le code ; il n’héberge ni chatbot, ni corpus. L’API ne doit pas être exposée à un réseau non fiable sans authentification, HTTPS, contrôle d’accès et limites de ressources. Les PDF et données d’indexation ne sont pas inclus.
